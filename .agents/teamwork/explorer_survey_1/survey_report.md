## 1. Executive Summary

The repository contains a clinically grounded ADHD intervention suite combining clinical surveys (Vanderbilt/SNAP-IV), 25 GDPT 2018 benchmark tasks across Grades 1–5, Draft-07 JSON schemas, a 2-stage LLM decomposition pipeline, and a production-grade FastAPI backend with WebSocket synchronization. The interactive presentation application (`index.html` / `out_index.html` generated by `generate_app.py`) delivers a responsive, zero-external-network-dependency dual-phone simulator featuring Web Audio API synthesis and 60fps GPU animations; however, it currently relies on in-memory single-DOM coupling. To achieve seamless cross-tab and cross-device operation, a **Tri-Layer Hybrid Sync Bus (`MiloSyncBus`)** combining in-memory loopback (0ms), `BroadcastChannel` with `localStorage` fallback (<2ms), and WebSocket (`/ws/sync`) with silent auto-degradation must be formalized into the ecosystem architecture.

## 3. Architecture Design: Dual-Device Simulator & State Synchronization

### 3.1 Dual-Device Simulator Modalities

The simulator must support three primary operator contexts:

| Modality | Description | Sync Medium | Target User |
|---|---|---|---|
| **Mode 1: Dual Split View (Side-by-Side)** | Both iPhone shells rendered side-by-side in a single viewport. Actions on Mom's phone immediately reflect on Leo's phone. | In-Memory Direct Dispatch (< 1ms) | Pitch presentations, judges, classroom demos on laptop/projector. |
| **Mode 2: 1-Click Role Switcher (Mock Login)** | Switches viewport to focus exclusively on either Child App or Parent App with full responsive scaling. | In-Memory State Hydration | Single-user device walkthrough simulating individual perspectives. |
| **Mode 3: Multi-Tab / Multi-Window Split** | Parent opens Tab 1 (`?role=parent`), Child opens Tab 2 (`?role=child`) across dual monitors or split screens. | BroadcastChannel + LocalStorage Bus (< 2ms) | Realistic testing of separate physical screens without server setup. |
| **Mode 4: True Physical Device Split** | Child on physical iPad, Parent on physical smartphone over local Wi-Fi. | WebSocket (`ws://<host>:8000/ws/sync`) | Real-world clinical home testing. |

---

### 3.2 Evaluation of Synchronization Mechanisms

We evaluated four synchronization architectures against zero-latency, local reliability, and zero-configuration requirements:

| Mechanism | Latency | Dependency | Cross-Tab | Cross-Device | Failure Mode & Recovery |
|---|---|---|---|---|---|
| **In-Memory DOM Bus** | **0ms** | None | ❌ No | ❌ No | Fails if opened in separate tabs. |
| **BroadcastChannel API** | **< 2ms** | Modern Browser API | ✅ Yes | ❌ No | Uncaught in `file://` if strict origin blocking applies. |
| **LocalStorage Storage-Event Bus** | **< 5ms** | LocalStorage API | ✅ Yes | ❌ No | Works in 100% of browsers; persists state across page reloads. |
| **FastAPI WebSocket (`/ws/sync`)** | **~5-15ms** | Python + Uvicorn server | ✅ Yes | ✅ Yes | Requires backend running; fails if user opens raw HTML file. |

### 3.3 The Recommended Solution: Tri-Layer Hybrid Sync Bus (`MiloSyncBus`)

To ensure flawless execution in every conceivable testing scenario (offline single-file presentation, dual browser tabs, or networked physical devices), we design the **Tri-Layer Hybrid Sync Bus**:

```
+---------------------------------------------------------------------------------------+
|                                    APPLICATION UI                                     |
|            [Parent Hub: Trạm Thấu Hiểu]       [Child Cockpit: Milo Quest]             |
+---------------------------------------------------------------------------------------+
                                           |
                                           v
+---------------------------------------------------------------------------------------+
|                                 MiloSyncBus (Facade)                                  |
|   - sendEvent(type, payload)                                                          |
|   - onEvent(type, callback)                                                           |
|   - getSyncedState() / setSyncedState(state)                                          |
+---------------------------------------------------------------------------------------+
           |                                   |                                   |
           v (Local / Split)                   v (Cross-Tab / Refresh)             v (LAN / Physical)
+-----------------------+           +-----------------------+           +-----------------------+
|  Layer 1: In-Memory   |           | Layer 2: Web Bus      |           | Layer 3: WebSocket    |
|  Loopback (0ms)       |           | BroadcastChannel +    |           | ws://<host>:8000/     |
|  Direct state update  |           | LocalStorage Fallback |           | ws/sync (Auto-retry)  |
|  within same window   |           | (< 2ms latency)       |           | (Graceful silent fail)|
+-----------------------+           +-----------------------+           +-----------------------+
```

#### Layer Mechanics:
1. **Layer 1 (In-Memory Loopback)**: Dispatches immediately to local handlers in the current DOM tree. Guarantees 0ms latency for the Dual Side-by-Side split view.
2. **Layer 2 (Cross-Tab Web Bus)**:
   - Uses `new BroadcastChannel('milo_quest_sync_bus')`.
   - On every emitted state change, writes serialized snapshot to `localStorage.setItem('milo_quest_state_v1', JSON.stringify(state))`.
   - Listens to `window.addEventListener('storage', ...)` as a secondary fallback if `BroadcastChannel` is blocked in restrictive browser modes.
   - Provides automatic state hydration when a tab reloads.
3. **Layer 3 (Network WebSocket with Silent Graceful Degradation)**:
   - Tries to open `ws://${window.location.hostname || 'localhost'}:8000/ws/sync?room_id=family_room_milo_01&role=${currentRole}`.
   - If connected: transmits events across LAN to remote devices.
   - If connection fails or drops (e.g., opened via `file:///` without backend): silently flags status as `offline_local_only` without throwing errors or displaying disruptive error modals. Auto-reconnects in background with exponential backoff.

## 6. Clinical & Pedagogical Alignment Analysis

### 6.1 Barkley Executive Function & Miller's 7±2 Law
- **Single-Focus Card**: The Focus Cockpit (`childSwitchScreen('workspace')`) completely hides irrelevant UI elements (no sidebars, no multi-exercise lists, no distracting banner ads). Only one atomic instruction card is visible at a time.
- **Micro-Task Length Constraints**: All tasks decompose into steps with instructions < 15 words and a single active verb (e.g., `Chạm`, `Chọn`, `Đọc`, `Nhập`).
- **Tactile Visual Timers**: Rather than displaying high-stress digital millisecond countdowns, the visual disc uses calming green-to-amber progress indicators. When time expires, it gracefully initiates a Soft Pause rather than an alarm buzzer.

### 6.2 RSD Shield & Emotion Co-Regulation
- **Error Externalization**: The system never produces harsh error sounds or red warning borders.
- **4-4-4 Box Breathing Engine**:
  - Inhale 4s (orb expands to 125%, sky-blue).
  - Hold 4s (orb glows teal, calming message).
  - Exhale 4s (orb deflates to 90%, indigo-blue).
  - Relax 4s (orb soft green).
  - Backed by synthesized 261.63Hz singing bowl chime every phase transition.

### 6.3 Parent Effort-Based Praise Coach
- **Carol Dweck Growth Mindset**: Telemetry-driven coaching encourages praising persistence ("Mẹ thấy con rất kiên trì tự hoàn thành 3 bước") rather than innate talent ("Con thông minh quá").
- **Toxic Phrase Guard**: Flags and warns against phrases that trigger RSD ("Sao mãi không xong?", "Tập trung vào!").

## 8. Architectural Blueprints for Downstream Implementation

### 8.1 Proposed `MiloSyncBus` Implementation Skeleton

```javascript
class MiloSyncBus {
  constructor(roomId = 'family_room_milo_01', defaultRole = 'dual') {
    this.roomId = roomId;
    this.role = defaultRole;
    this.handlers = new Map();
    this.channel = null;
    this.ws = null;
    this.isWsConnected = false;
    this.storageKey = `milo_sync_state_${this.roomId}`;

    this.initBroadcastChannel();
    this.initStorageListener();
    this.initWebSocket();
  }

  initBroadcastChannel() {
    try {
      if (typeof BroadcastChannel !== 'undefined') {
        this.channel = new BroadcastChannel(`milo_bus_${this.roomId}`);
        this.channel.onmessage = (event) => this.handleIncomingEvent(event.data, 'broadcast');
      }
    } catch (e) {
      console.warn('BroadcastChannel unavailable, falling back to LocalStorage', e);
    }
  }

  initStorageListener() {
    window.addEventListener('storage', (e) => {
      if (e.key === `milo_event_${this.roomId}` && e.newValue) {
        try {
          const data = JSON.parse(e.newValue);
          this.handleIncomingEvent(data, 'storage');
        } catch (err) {}
      }
    });
  }

  initWebSocket() {
    // Only attempt if not opened directly from file:/// or if explicitly enabled
    const host = window.location.hostname || 'localhost';
    const port = '8000';
    const wsUrl = `ws://${host}:${port}/ws/sync?room_id=${this.roomId}&role=${this.role}`;

    try {
      this.ws = new WebSocket(wsUrl);
      this.ws.onopen = () => { this.isWsConnected = true; };
      this.ws.onmessage = (e) => {
        try {
          const data = JSON.parse(e.data);
          this.handleIncomingEvent(data, 'websocket');
        } catch (err) {}
      };
      this.ws.onclose = () => {
        this.isWsConnected = false;
        // Silent reconnect attempt after 5s
        setTimeout(() => this.initWebSocket(), 5000);
      };
      this.ws.onerror = () => { this.ws.close(); };
    } catch (e) {
      this.isWsConnected = false;
    }
  }

  emit(eventType, payload) {
    const event = {
      event_type: eventType,
      sender: this.role,
      room_id: this.roomId,
      timestamp: Date.now(),
      payload: payload
    };

    // 1. Local loopback (0ms)
    this.triggerLocal(eventType, event);

    // 2. BroadcastChannel
    if (this.channel) {
      this.channel.postMessage(event);
    }

    // 3. LocalStorage event bus
    try {
      localStorage.setItem(`milo_event_${this.roomId}`, JSON.stringify(event));
    } catch (e) {}

    // 4. WebSocket transmission
    if (this.ws && this.isWsConnected) {
      this.ws.send(JSON.stringify(event));
    }
  }

  on(eventType, callback) {
    if (!this.handlers.has(eventType)) {
      this.handlers.set(eventType, []);
    }
    this.handlers.get(eventType).push(callback);
  }

  triggerLocal(eventType, event) {
    const cbs = this.handlers.get(eventType) || [];
    cbs.forEach(cb => {
      try { cb(event.payload, event); } catch (e) { console.error(e); }
    });
  }

  handleIncomingEvent(event, transport) {
    if (!event || !event.event_type) return;
    // Prevent echo if message originated from self (unless local loopback)
    if (event.sender === this.role && transport !== 'loopback') return;
    this.triggerLocal(event.event_type, event);
  }
}
```
